# 소닉 애니메이션 뷰어 개발 문서

## 1. 목적과 기준 문서

`PRE_PRD.md`와 사용자의 추가 지시를 바탕으로 `sonic-sprite.png`에 포함된 소닉의 모든 동작을 순서대로 감상하는 데스크톱 애니메이션 뷰어를 개발한다. 동작별 반복 횟수와 전환 대기 시간을 정확하게 제어하고, 원본 픽셀 크기가 달라도 같은 시작 위치와 같은 표시 크기를 사용한다. 이동이 포함된 동작은 애니메이션 재생과 동시에 화면상의 캐릭터 위치도 이동한다.

개발 위치는 `Labs/LEC09`이며, 개발 브랜치는 `feature/lec09-sonic-animation-viewer`다. 이 문서는 요구사항과 구현·검증 계획을 정의한다. 아래 체크리스트는 개발 완료를 의미하지 않는다.

## 3. 범위와 기본 설계

### 3.1 필수 구현 범위

- 실행하면 별도 조작 없이 첫 동작부터 자동 재생한다.
- 각 동작의 프레임 영역과 순서를 데이터로 정의한다.
- 재생, 반복 횟수 계산, 대기, 다음 동작 전환을 구현한다.
- 모든 동작을 화면 중앙에서 동일한 너비와 높이로 시작한다. 정지 동작은 위치를 유지하고, 이동 동작은 애니메이션과 함께 실제 화면 좌표를 변경한다.
- 재생 중과 대기 중 모두 창 닫기와 `Esc`로 종료할 수 있다.
- 이미지 누락이나 잘못된 동작 데이터에는 원인을 알 수 있는 오류를 표시한다.

### 3.2 원문에 없는 항목에 대한 구현 기본값

다음은 요구사항을 구현하기 위한 기본값과 정책이다. 창 크기와 목표 표시 크기 등의 수치는 실제 화면 검수 결과에 따라 조정하되 R01~R12를 유지한다. 공통 시작 위치·동일 크기 및 이동 동작의 실제 이동은 필수 요구사항이다.

| 항목 | 기본값 또는 정책 |
| --- | --- |
| 창 크기 | 800 × 600 픽셀 |
| 프레임 재생 속도 | 초당 10프레임, 동작별로 필요하면 별도 지정 |
| 목표 표시 크기 | 모든 프레임의 캐릭터를 공통 너비 300 × 높이 300 픽셀로 표시 |
| 확대 가시성 목표 | 공통 목표 높이가 창 높이의 약 40~60%를 차지하도록 조정 |
| 배경 | 소닉의 파란 몸체와 흰 장갑이 구분되는 단색 배경 |
| 표시 기준 | 공통 시작 중심은 `(400, 300)`. 정지 동작은 고정, 이동 동작은 시작 중심에 이동량을 더해 표시 |
| 이동 방식 | 동작별 이동 유형·방향·거리·경로를 정의하고 재생 시간에 맞춰 자동 이동 |
| 대기 중 표시 | 현재 동작의 마지막 프레임과 최종 위치를 유지하고 이동 정지 |
| 재생 순서 | 이미지에서 동작 묶음을 위에서 아래로, 같은 높이에서는 왼쪽에서 오른쪽으로 등록 |
| 한 프레임 동작 | 기본 프레임 시간 동안 표시하는 것을 1회 재생으로 계산 |
| 이미지 경로 | 소스 파일이 있는 디렉터리를 기준으로 해석 |

원본 크기에 맞춰 프레임별 가로·세로 배율을 각각 계산해 화면상의 너비와 높이를 같게 만든다. 목표 크기를 조정할 때는 전체 동작에 같은 값을 적용한다. 공중 동작과 공 형태도 목표 크기는 유지하고, 실제 이동 여부는 동작 분석 결과에 따라 결정한다. 이동 경로 전체에서 모든 프레임이 잘리지 않도록 여백을 확보한다.

### 3.3 이번 개발에서 제외하는 기능

사용자 동작 선택, 재생 속도 조절 UI, 일시정지 버튼, 사운드, 키보드·마우스로 캐릭터를 직접 이동하는 조작, 충돌 처리, 이미지 편집, 영상 내보내기, 실행 파일 패키징은 구현 범위에 포함하지 않는다. 동작 재생에 따른 자동 이동은 필수 구현 범위에 포함한다. 개발 중 좌표 검수용 표시나 로그는 사용할 수 있다.

## 4. 스프라이트 분석과 동작 데이터

### 4.1 이미지 분석 원칙

제공 이미지에는 여러 줄의 소닉 프레임과 제목·제작자 표기·하단 장식 캐릭터가 함께 있다. 프레임 크기와 간격이 일정하지 않으므로 전체 이미지를 동일한 격자로 나누지 않는다. 또한 한 줄이 반드시 하나의 동작이라고 가정하지 않는다.

모든 소닉 포즈와 회전·공 형태의 소닉 프레임을 검토해 동작 목록에 포함한다. 제목, 제작자 표기, 하단의 다른 캐릭터 등 소닉 동작과 무관한 요소는 재생 대상에서 제외한다. 연결 관계가 불명확한 포즈는 임의로 버리지 않고 단독 동작 또는 별도 묶음으로 분류한 뒤 검수한다.

정확한 동작 수, 동작명, 프레임 수와 좌표는 구현 초반의 이미지 분석에서 확정한다. 원문에 없는 동작 이름이나 프레임 수를 이 문서에서 확정된 사실로 지정하지 않는다.

### 4.2 동작 목록의 완료 조건

개발 초반에 다음 항목을 정리하고, 같은 정보를 단일 소스 파일의 데이터와 주석에 반영한다.

| 항목 | 내용 |
| --- | --- |
| 동작 ID | 순서와 무관하게 동작을 구분하는 고유 값 |
| 동작명 | 실제 포즈에 맞춘 설명용 이름 |
| 원본 위치 | 이미지의 어느 줄·구간에 해당하는지 설명 |
| 프레임 목록 | 재생 순서대로 정렬한 잘라내기 영역 |
| 프레임 수 | 프레임 목록의 길이 |
| 프레임 시간 | 기본값 0.1초, 필요한 경우 동작별 조정 |
| 캐릭터 영역 | 투명 여백을 제외한 캐릭터와 해당 프레임의 잔상 전체를 포함하는 최소 사각형 |
| 정렬 정보 | 캐릭터 영역 중심을 현재 화면 좌표에 맞추는 좌표 보정 정보 |
| 이동 정보 | 정지·수평 이동·도약 등 이동 유형, 방향, 거리 또는 높이, 재생 진행률에 따른 경로 |
| 검수 여부 | 누락, 잘림, 주변 프레임 혼입을 확인한 결과 |

완성된 목록과 원본 이미지를 대조해 모든 소닉 프레임이 어느 동작에 속하는지 설명할 수 있어야 한다. 같은 프레임을 여러 동작에서 재사용한다면 그 이유를 주석에 남긴다.

### 4.3 좌표 및 데이터 규칙

- 각 프레임은 `left`, `top`, `width`, `height`를 갖는 사각형으로 정의한다. 원본 분석 좌표는 이미지 왼쪽 위를 원점으로 통일한다.
- 렌더링에 필요한 아래쪽 원점 좌표는 이미지 높이를 `H`라고 할 때 `bottom = H - top - height`로 변환한다.
- 모든 좌표와 크기는 원본 이미지의 픽셀 단위이며, 확대 배율을 원본 잘라내기 좌표에 적용하지 않는다.
- 프레임 크기는 양수이고, 잘라내기 영역 전체가 이미지 경계 안에 있어야 한다.
- 모든 동작에는 최소 1개의 프레임이 있어야 하고, 프레임 시간은 양수여야 한다.
- 캐릭터의 손발과 잔상을 포함하되 주변 동작, 제목, 제작자 표기가 섞이지 않도록 한다.
- 투명 영역과 배경색은 실제 이미지 로딩 결과를 확인한다. 사각형 배경이 드러나는 경우 배경색과 표시 방식을 조정한다.

### 4.4 공통 시작 위치·동일 크기 표시 규칙

1. 각 프레임에서 캐릭터와 해당 동작의 잔상을 포함한 실제 표시 영역을 확인하고, 바깥의 투명 여백을 제외한다. 여백이 다른 프레임을 같은 사각형에 그리는 것만으로 크기 통일을 완료했다고 판단하지 않는다.
2. 표시 영역의 원본 너비를 `w`, 높이를 `h`, 공통 목표 크기를 `W`, `H`라고 할 때 가로 배율은 `W / w`, 세로 배율은 `H / h`로 계산한다.
3. 모든 동작의 시작 중심은 `(창 너비 / 2, 창 높이 / 2)`이며 출력 너비 `W`, 높이 `H`는 공통이다. 이동 중에는 시작 중심에 동작별 이동량을 더한 좌표에 그린다. 원본 종횡비가 다르면 가로·세로 배율이 달라질 수 있으며, 화면상의 동일 너비·높이를 우선한다.
4. 원본 좌표와 여백 차이에 대한 보정은 캐릭터 영역을 정렬하는 용도로만 사용한다. 프레임 정렬 보정과 실제 이동량을 분리하여, 의도한 이동을 중앙 정렬로 상쇄하지 않는다.
5. 재생 중, 반복 시작, 동작 전환, 1초 대기 중 모두 같은 크기 규칙을 적용한다. 렌더링 결과의 캐릭터 영역 중심은 현재 이동 좌표와 일치해야 하며, 중심과 너비·높이는 픽셀 반올림에 따른 1픽셀 이내의 오차만 허용한다.

## 5. 재생 동작 명세

### 5.1 1회 재생의 정의

프레임이 `N`개인 동작의 1회 재생은 첫 프레임부터 마지막 프레임까지 순서대로 각각 지정 시간만큼 표시하는 것이다. 마지막 프레임의 표시 시간이 끝난 시점에 완료 횟수를 1 증가시킨다. 마지막 프레임에 진입하는 순간에는 완료 횟수를 올리지 않는다.

고정 프레임 시간이 `d`초일 때 한 동작의 총 재생 시간은 `5 × N × d`초이며, 이어서 대기 시간 1초가 추가된다. 예를 들어 4프레임을 각 0.1초씩 표시하면 재생 2초 후 대기 1초를 거친다.

### 5.2 상태와 전환

| 현재 상태 | 조건 | 처리 | 다음 상태 |
| --- | --- | --- | --- |
| 초기화 | 이미지·데이터 준비 완료 | 첫 동작, 첫 프레임, 완료 횟수 0, 공통 시작 위치로 시작 | 재생 |
| 재생 | 현재 프레임 시간이 지나고 마지막 프레임이 아님 | 다음 프레임으로 이동 | 재생 |
| 재생 | 마지막 프레임 시간이 지나고 완료 횟수가 5 미만 | 완료 횟수를 증가시키고, 증가 후에도 5 미만이면 첫 프레임으로 이동 | 재생 |
| 재생 | 완료 횟수가 5가 됨 | 마지막 프레임과 이동 종료 위치를 유지하고 1초 대기 시작 | 대기 |
| 대기 | 1초 미만 경과 | 화면과 입력 처리를 계속 수행 | 대기 |
| 대기 | 1초 경과 | 다음 동작의 첫 프레임 선택, 완료 횟수·시간·이동량 초기화, 공통 시작 위치로 복귀 | 재생 |
| 재생 또는 대기 | 창 닫기 또는 `Esc` | 루프 종료 및 창 자원 정리 | 종료 |

마지막 동작 다음에는 첫 동작을 선택한다. 동작 변경 시 이전 동작의 반복 횟수를 이어받지 않는다.

### 5.3 시간 처리

프레임 진행은 렌더링 루프 횟수가 아닌 단조 증가 시간에 기반한 경과 시간으로 계산한다. 재생 상태에서는 프레임 시간을 누적하고, 일반적인 짧은 지연으로 남은 시간은 다음 프레임 계산에 반영한다.

5회 완료 시에는 실제로 대기 상태에 진입한 시점을 기록하고 그 시점부터 1초를 센다. 재생 상태에서 남은 시간을 대기에 넘겨 휴식 시간을 줄이지 않는다. 대기 종료 시 다음 동작은 첫 프레임부터 새로 시작한다. 장시간 창 이동이나 디버거 정지 중에는 일부 프레임의 화면 표시를 보장하지 않지만, 상태와 반복 횟수가 범위를 벗어나지 않아야 한다.

1초 대기를 하나의 긴 정지 호출로 구현하지 않는다. 대기 중에도 입력 처리와 화면 갱신을 지속한다. 정상 실행에서 대기 종료는 1초가 지난 뒤 처음 처리되는 업데이트 시점이며, 관찰 오차는 일반적인 업데이트 한 주기 수준을 목표로 한다.

### 5.4 이동 동작 재생

**이동이 들어가는 동작의 경우는 애니메이션과 동시에 이동도 되어야 한다.** 스프라이트 프레임을 바꾸는 것과 함께 캐릭터의 화면 좌표를 변경한다. 이동 대상은 이미지 분석 단계에서 확정하고 모든 동작에 정지 또는 이동 정보를 명시한다. 걷기·달리기·구르기·점프 등은 분류 예시이며 실제 이미지에 해당 동작이 있는지 확인한 뒤 적용한다.

- 프레임 재생과 위치 갱신은 같은 경과 시간을 사용한다. 이동은 화면 갱신마다 계산하여 프레임 교체 사이에도 부드럽게 진행한다. 한 프레임으로 구성된 이동 동작도 위치를 갱신한다.
- 수평 이동은 캐릭터가 향하는 방향으로 진행한다. 기본 정책은 한 동작의 5회 재생 전체에 걸쳐 정해진 거리를 연속 이동하는 것이다. 매 반복마다 시작 위치로 되돌리지 않는다.
- 도약은 해당 프레임의 상승·정점·하강에 맞춘 경로를 사용한다. 제자리 도약은 1회 재생마다 기준 높이로 착지하고, 전진 도약은 수평 이동을 함께 적용한다. 정지 자세나 단순 회전은 실제 이동이 필요한 동작으로 분류한 경우에만 이동한다.
- 동작 시작 시 공통 시작 위치에서 출발한다. 5회 재생 종료 시 마지막 프레임과 경로의 최종 위치를 1초간 유지하고, 다음 동작 시작 시 위치와 이동 시간을 초기화한다. 마지막 동작에서 첫 동작으로 돌아갈 때도 같은 규칙을 적용한다.
- 이동 거리·속도·도약 높이는 동작별 데이터로 정의하고 검수에서 확정한다. 경로는 목표 표시 크기와 창 크기를 고려해 5회 재생 동안 캐릭터 전체가 화면 안에 남도록 설계한다. 화면 경계에 도달한 뒤 제자리 재생으로 바뀌지 않도록 처음부터 이동 거리를 맞춘다.
- 이동 여부와 관계없이 표시 너비·높이는 동일하게 유지한다. 원본 여백 때문에 발생하는 위치 튐과 동작에 필요한 실제 이동을 구분해 검수한다.

## 7. 실행 환경과 오류 처리

- Python 3와 pico2D가 설치된 환경을 전제로 한다. 실제 검증에 사용한 버전은 개발 완료 시 실행 안내에 기록한다.
- `Labs/LEC09`에서 `python sonic_animation_viewr.py`로 실행할 수 있어야 한다.
- 저장소 루트에서도 `python Labs/LEC09/sonic_animation_viewr.py`로 같은 이미지를 불러올 수 있어야 한다.
- Python 표준 라이브러리와 pico2D를 사용한다. 별도의 런타임 라이브러리가 필요해지는 설계는 피한다.
- 이미지 누락·로딩 실패 시 문제가 된 경로와 실패 원인을 알 수 있는 메시지를 남기고 종료한다.
- 잘못된 프레임 데이터는 해당 동작과 프레임을 식별할 수 있는 메시지로 보고한다.
- 정상 종료 및 초기화 이후 오류 종료에서 열린 창을 정리한다.

| 40 | 실행 안내와 요구사항 최종 대조 기록 | R01~R12 충족 여부, 한국어 커밋 이력 및 검증 환경 기록 | `문서: 소닉 뷰어 실행 방법과 완료 기준 기록` |

28~29단계의 묶음은 10단계에서 확정한 재생 목록 순서를 기준으로 나눈다. 프레임 수가 많으면 더 작은 커밋으로 나눌 수 있으며, 전체 개발 단계 수는 30단계 이상을 유지한다. 검증에서 문제가 발견되면 해당 문제를 수정한 후 다음 단계로 진행한다.

## 10. 최종 산출물과 완료 조건

최종 폴더 구성은 다음을 기준으로 한다.

```text
Labs/LEC09/
├── PRE_PRD.md                 # 원본 요구사항
├── PRD.md                     # 개발 명세와 검증 기록
├── sonic-sprite.png           # 원본 이미지
└── sonic_animation_viewr.py   # 단일 실행 소스
```

- [ ] 실행 소스가 지정된 이름의 Python 파일 하나로 구성되어 있다.
- [ ] 전체 소닉 동작 목록과 프레임 좌표 검수가 완료되어 있다.
- [ ] 각 동작이 정확히 5회 재생되고 1초 대기한다.
- [ ] 마지막 동작 뒤에도 대기 후 처음부터 무한 반복한다.
- [ ] 모든 동작이 공통 시작 위치에서 시작하고, 원본 크기와 관계없이 같은 너비·높이로 충분히 크게 표시된다.
- [ ] 이동 동작은 애니메이션과 동시에 실제 화면 좌표가 변하고, 정지 동작은 위치를 유지한다.
- [ ] 이동 중 크기와 화면 여백을 유지하며, 1초 대기 중 정지하고 다음 동작 시작 시 위치를 초기화한다.
- [ ] 투명 여백을 제외한 실제 캐릭터 영역 기준으로 정렬·크기·화면 여백 검수를 통과한다.
- [ ] 재생·대기 중 종료와 오류 처리 검증을 통과한다.
- [ ] 최소 30단계의 실제 개발 변경과 단계별 검증을 커밋 기록으로 확인할 수 있다.
- [ ] 모든 개발 커밋의 제목과 본문을 한국어로 작성한다.
- [ ] 검증 환경, 실행 방법, V01~V20 결과와 남은 제한사항을 기록한다.

현재 미확정 항목은 정확한 동작 목록·프레임 및 캐릭터 영역 좌표·최종 공통 목표 너비와 높이·동작별 재생 속도 조정 여부·이동 대상과 경로·이동 거리와 속도·검증 환경 버전이다. 각각 이미지 분석, 화면 검수, 실행 검증 단계에서 확정한다. 공통 시작 위치와 동일 표시 크기, 이동 동작의 애니메이션·이동 동시 재생, 한국어 커밋 규칙은 확정 요구사항이다.
